# Chat Yaiwes fromtend

La fuente única del frontend está en `chat router/Chat UI fromtend/` del repositorio Router inteligente universal, no en la ubicación anterior `chat router/chat fromtend/`. La entrada es `chat Yaiwes fromtend.html`. Carga `styles/tokens.css`, `styles/chat.css` y `src/app.js` como módulos separados. `src/panels/chat.js` es el único panel de chat; `src/panels/settings.js` edita botones y comandos. Los archivos `src/panels/panel-03.js` y `panel-04.js` son reservas separadas sin interfaz ni navegación; los otros paneles solicitados en los pasos 6–8 no se implementan ni se declaran terminados aquí. Cada selector y ventana tiene su archivo en `src/windows/`. No se modificó `chat router/space/`.

## Vista de revisión sin servidor

El HTML fuente **no funciona como archivo suelto**: necesita conservar `styles/` y `src/` y servirlos por HTTP(S), porque el navegador restringe los módulos externos abiertos con `file://`. Si esos recursos no se cargan, la página muestra un diagnóstico en lugar de quedar vacía. Para revisar directamente un solo archivo: `npm ci` y `npm run build:review` generan `chat Yaiwes fromtend.revisar.html`. Abre ese archivo generado; contiene el CSS y JavaScript reales de los módulos empaquetados localmente, sin CDN ni respuestas ficticias. Es un artefacto de revisión ignorado por Git, **no** la fuente editable ni un despliegue. La interfaz se puede recorrer localmente; si el navegador bloquea `localStorage`, las ediciones funcionan solo durante esta sesión y se advierte que no persisten. Las acciones remotas permanecen bloqueadas sin host/backend y autenticación.

## Composición corregida contra Maxbry UI

La cabecera (`src/components/chat-topbar.js`) deja visibles el nombre, la marca Y, Configuración y un menú para Nuevo chat/Exportar. El composer (`src/components/chat-composer.js`) usa el modelo como desplegable, un área de texto de dos líneas, el nivel de razonamiento, voz, watchdog, enviar y el botón `+`. No se renderizan filas horizontales permanentes de cinco selectores ni ocho controles.

El `+` abre `src/windows/tools.js`: adjuntos y documentos (con comandos separados), habilidades, conectores, cinco selectores, ocho interruptores y doce funciones. `selectors.js` agrupa los lanzadores; `selector-1.js` a `selector-5.js` siguen siendo ventanas independientes. `controls.js` presenta los ocho controles como filas con nombre, descripción y switch. Los modelos, niveles y selectores usan un borrador cancelable; solo Aplicar cambia el estado, y un comando remoto necesita confirmación real. Los modelos tienen búsqueda y excluyen DeepSeek/auto. Los errores también aparecen dentro del diálogo activo.

Configuración conserva los nombres, descripciones, opciones, modelos y actionId. `src/actions/settings-transfer.js` permite exportar, importar (JSON versionado y validado) y restablecer la configuración con confirmación previa al reemplazo. Estos archivos **no deben contener secretos**. `src/components/theme-picker.js` y `src/components/theme-palette.js` muestran siete paneles de color seleccionables: Gris V07 como predeterminado, Little, Matte y Blanco como alternativas canónicas, y Crystal, Orange y Blue como paletas de referencia marcadas como no aprobadas, sin mezclar sus tokens. ## Transporte de plugins

`src/bridge.js` emite `yaiwes:ui-action` y exige confirmación `{ok:true}` de `window.YAIWES_PLUGIN_BRIDGE.execute(actionId,payload)` para operaciones remotas. El evento por sí solo no es confirmación. `src/plugins/same-origin-chat.js` instala ese contrato **solo** en HTTP(S) si el host no lo había proporcionado. Usa rutas existentes del API: `GET /chat/providers`, `GET /chat/providers/{provider}/models`, `POST /chat/documents` y `POST /chat/send`. Usa `credentials: same-origin`; no contiene ni solicita claves. Bloquea `auto` y modelos/proveedores DeepSeek incluso cuando el usuario los configura manualmente. El modelo se selecciona explícitamente en formato `proveedor/id-del-modelo` y se comprueba que la respuesta del backend use ese mismo proveedor/modelo. Los documentos reales se envían Base64 a `/chat/documents` (máximo 10 MiB) y se consideran subidos únicamente tras recibir un ID real. Los mensajes sin texto, los adjuntos no subidos, los modos que el API no admite y las respuestas inválidas fallan explícitamente. Una conversación nueva reinicia el ID local y descarta respuestas tardías de la conversación anterior.

**Estado de integración:** el servicio `chat router/space/app.py` todavía sirve su propio `index.html`, **no** esta carpeta. La API inspeccionada está en `router inteligente universal/integration/chat_mvp/router.py`: catálogo por proveedor, envío y documentos requieren una `X-API-Key`/Bearer; **una cookie same-origin no basta**. Para uso real, un host autorizado debe servir estos archivos bajo el mismo origen que `/chat/*` **y** autenticar las peticiones mediante un relevo seguro del lado servidor, o inyectar su propio `YAIWES_PLUGIN_BRIDGE` que implemente ese relevo. El adaptador no agrega secretos, no obtiene claves del navegador y por sí solo recibirá HTTP 401 en esas rutas; nunca debe ponerse la API key en Configuración/localStorage. No se ha ejecutado una petición real de esta UI al servicio. El bus Fables encontrado registra/valida plugins Python, pero no expone una invocación HTTP verificada para esta UI; no se afirma que Fables o DeepSeek Harness hayan ejecutado estas acciones. DeepSeek Harness solo sería infraestructura de plugins, nunca modelo de inferencia.

Los comandos configurables fuera de `chat.models`, `chat.attach` y `chat.send` requieren un bridge del host con implementación propia: voz, watchdog, habilidades, conectores, 8 toggles, 5 selectores, 12 funciones y los 8 niveles avanzados. El API verificado solo acepta `mode: direct` o `agent`; el adaptador no inventa niveles avanzados. El modo local `mode-1` se envía como `direct` sin afirmar que haya razonamiento avanzado; los demás modos fallan como `MODE_NOT_SUPPORTED_BY_CHAT_API` si se usa este adaptador. Seleccionar modelos/modos sin actionId es una selección **local**, no confirmación del backend.

Si el host devuelve 401 (incluso como HTML), el adaptador presenta `BACKEND_HTTP_401` en vez de diagnosticar erróneamente JSON inválido. Si se inicia una conversación nueva mientras sigue pendiente el permiso de micrófono, las pistas de audio obtenidas para la conversación anterior se cierran y no se crea una grabación huérfana.

Las etiquetas/descripciones y `actionId` de cada control se editan en Configuración. Temas: Gris V07 principal; Little, Matte y Blanco canónicos; Crystal, Orange y Blue solo como referencia etiquetada. Idiomas: `es`, `en`, `fr` y `pt`, con etiquetas editadas por el usuario preservadas. La configuración se guarda en `localStorage`; no guardes credenciales ni código allí. Los mensajes y archivos no se persisten. La exportación del chat y de la configuración descarga JSON local real, no una respuesta remota. `Nuevo chat` borra solamente el estado local.

Validación estática sin servidor ni navegador: `npm test` y `npm run check` con Node.js disponible. La comparación visual, la integración con el host y el despliegue siguen sin probar, pendientes de autorización. No se usan GitHub Actions, Git LFS ni Vercel desde este módulo.
