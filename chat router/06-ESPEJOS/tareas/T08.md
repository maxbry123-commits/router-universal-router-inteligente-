## Archivos
1. `engine.py` — contrato común `class Engine: id, capabilities; async can_handle(task); async execute(task, context); async verify(result)`.
2. `capability_engine.py` — lee un registro de componentes (id, provides, requires, compatible_with, conflicts_with, runtime) y dado un objetivo
   devuelve capacidades necesarias → candidatos por capacidad → composición compatible (sin conflictos) + auditoría de descarte (por qué no se eligió cada uno).
   Regla: "ningún componente invisible": falla si hay carpetas de componentes sin registrar.
3. `canvas_engine.py` — modelo de página determinista: createPage, addSection, addComponent, moveComponent, setProperty, exportJSON (sin navegador).
4. `layout_engine.py` — geometría sin LLM: grid/flex, gap, snap, bounds, breakpoints (entrada viewport + elementos + columnas → posiciones/tamaños).
5. `action_flow_engine.py` — botón → action_id → handler; compila un flujo visual {validate, serialize, persist, notify} a DAG ejecutable; ningún botón muerto.
6. `sandbox_engine.py` — ejecuta Python en subproceso aislado con timeout y límite de salida; JS vía `node -e` si existe (si no, GAP). Devuelve stdout/stderr/rc.
7. `qa_engine.py` — comprobaciones deterministas del JSON de página: componentes con acción, solapes de layout, tamaños táctiles mínimos (44 px), breakpoints.
8. `registry.py` — ENGINE_REGISTRY {"ui.capability", "ui.canvas", "ui.layout", "ui.actions", "code.sandbox", "qa.visual"} y `ejecutar_en_paralelo(tareas)` con asyncio.gather.
9. `tests/test_motores.py` — pytest: un "dashboard móvil" recorre capability → canvas → layout → actions → qa → PASS; casos de conflicto y botón muerto.
10. `README.md` — micro resumen + micro diagrama.
