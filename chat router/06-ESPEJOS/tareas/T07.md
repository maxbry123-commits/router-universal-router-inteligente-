# T07 — Puerta de evidencia (Evidence/Search Gate) con los 12 goals del Director
ALCANCE: chat router/11-EVIDENCIA
ARCHIVOS: parser.py, goals.py, compilador_busquedas.py, buscadores.py, extractor.py, ranking.py, evidence_pack.py, verificador.py, puerta.py, tests/__init__.py, tests/test_puerta.py, README.md

## Fuente (literal del Director)
Documento 26 en `chat router/00-INSTRUCCIONES/INPUT-BLOCK-VERBATIM-PARTE-5-C-DOCS-24-26-M40.md`: INPUT → PARSER DETERMINISTA → 12 GOALS DE ENTRADA →
COMPILADOR DE BÚSQUEDAS (plantillas, sin LLM) → MOTORES → EXTRACTOR EXACTO (sin LLM) → RANK/FUSIÓN (BM25 + autoridad + recencia + coincidencia +
corroboración − duplicado; Reciprocal Rank Fusion) → EVIDENCE PACK → [LLM filtro opcional] → EJECUTOR → CLAIMS → BÚSQUEDA DE VERIFICACIÓN →
12 GOALS DE SALIDA → SHERIFF (PASS / INCOMPLETE / CONTRADICTION / FAIL). Regla: la IA que ejecutó no cierra su propio trabajo.

## Archivos
1. `parser.py` — reglas/regex → {task_type (SEARCH, INSTALL, DOWNLOAD, EXTRACT, DEPLOY, MODIFY_CODE, DEBUG, TEST, COMPARE, AUDIT, RESEARCH, VERIFY), targets, requirements, constraints, forbidden, verification}. Sin LLM.
2. `goals.py` — G01..G12 (Objetivo, Entidades, Restricciones, Dependencias, Fuente oficial, Versión, Configuración, Integración, Ejecución, Tests, Contradicciones, Evidencia) con pregunta de entrada, comprobación de salida y plantillas de consulta.
3. `compilador_busquedas.py` — plantillas por task_type (DEPLOY, DEBUG, VERSION…) → lista de consultas. Sin LLM.
4. `buscadores.py` — fan-out: GitHub search API (repos/issues/código, token por env), documentación por URL (urllib), búsqueda local en el repo. Resultados normalizados {query, source, url, title, date, snippet, source_type, retrieved_at}. Modo SIMULADO.
5. `extractor.py` — HTML/Markdown → fragmentos por título/párrafo/bloque de código con términos coincidentes. Sin LLM.
6. `ranking.py` — BM25 propio (stdlib) + autoridad + recencia + corroboración − duplicado; RRF para fusionar motores.
7. `evidence_pack.py` — {task, known_facts, requirements, constraints, conflicts, unknown, sources}, tope 8K tokens aprox.
8. `verificador.py` — claims del resultado → comprobaciones (archivo existe, HTTP responde, versión coincide, tests pasan).
9. `puerta.py` — `antes(input) -> evidence_pack` y `despues(input, resultado) -> PASS|INCOMPLETE|CONTRADICTION|FAIL` con detalle por goal.
10. `tests/test_puerta.py` — pytest SIMULADO de todo el flujo (incluye un caso FAIL y uno CONTRADICTION).
11. `README.md` — micro resumen + micro diagrama.
