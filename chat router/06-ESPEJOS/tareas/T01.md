# T01 — Gobierno del equipo (Sheriff, Judge, Sentinel, contratos, MirrorManager)
ALCANCE: chat router/05-AGENTES/gobierno

## Objetivo
Implementar en Python (stdlib + pyyaml si hace falta) las piezas de CÓDIGO del gobierno de agentes, tal como las definió el Director
en `chat router/00-INSTRUCCIONES/INPUT-BLOCK-VERBATIM-PARTE-5-B-DOCS-22-23.md` (documentos 22 y 23). Copia su diseño; no inventes otro.

## Archivos a entregar (todos dentro del ALCANCE)
1. `contratos.py` — dataclasses `Job` {job_id, objective, scope, acceptance, state, attempt, evidence, issues} y `Result`
   {job_id, agent, status, changed_files, tests, issues, evidence, next_action} (doc 22) + `Task` {id, objective, role, dependencies,
   allowed_paths, acceptance, evidence} y `State` enum INPUT…BLOCK (doc 23). Con `to_dict/from_dict` y validación de campos obligatorios.
2. `sheriff.py` — clase `Sheriff.validate(plan) -> (bool, motivo)` exactamente con las reglas del doc 23 (acceptance obligatorio,
   dependencias válidas, sin rutas absolutas ni `..`). Añadir: prohibir rutas que empiecen por `.github/` o `router inteligente universal/`.
3. `judge.py` — `Judge.decide(task, evidence, hermes_review, openclaw_review) -> "PASS"|"REVISE"|"BLOCK"` (doc 23).
4. `sentinel.py` — `Sentinel.inspect(task_state) -> {"action": RECOVER|REASSIGN|BLOCK|CONTINUE}` (doc 23) + detector de atasco:
   mismo error 3 veces seguidas → REASSIGN; heartbeat más viejo que N minutos → REASSIGN.
5. `mirror_manager.py` — `MirrorManager.create(job_id, system)` con `SYSTEM_MAP` (doc 22) usando `git worktree add ../mirrors/<job> -b mirror/<job>`;
   `restrict(allowed_paths)`; `diff()`; `merge_selectivo()` solo si Sheriff aprueba; `keep_for_debug()` si falla. Sin tocar main directamente.
6. `tests/test_gobierno.py` — pytest: al menos 3 casos por clase (PASS y fallos). Ejecuta `python -m pytest chat\ router/05-AGENTES/gobierno/tests -q`.
7. `README.md` — micro resumen + micro diagrama de flujo (Rowboat → Hermes+OpenClaw → Sheriff → Ruflo → Colmena → Sentinel → revisión → Judge).
